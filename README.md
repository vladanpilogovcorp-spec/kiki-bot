# Бот очереди выносов — «Кики»

Рабочий Telegram-бот: заявки на выносы/кальян, статусы «Собираются → Готовы →
Объявлено → Выполнено», VIP-приоритет, пауза очереди на время шоу-номера
(команды менеджера), авто-теги MC и музыкального работника при заказе песни.

## Шаг 1. Получить токен бота (2 минуты)

1. Открой Telegram, найди **@BotFather**
2. Отправь ему `/newbot`
3. Придумай имя бота (например, «Кики Выносы») и юзернейм, оканчивающийся на `bot`
   (например, `kiki_vynosy_bot`)
4. BotFather пришлёт токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`
   — сохрани его, он понадобится дальше

## Шаг 2. Настроить бота под себя

Открой `bot.py` и в самом верху при желании поправь:

- `MC_USERNAME` — юзернейм MC (без `@`), которого тегать при заказе песни
- `MUSIC_USERNAME` — юзернейм того, кто ищет музыку
- `MANAGER_IDS` — если хочешь ограничить `/pause` и `/resume` только
  менеджерам, впиши их Telegram user_id через запятую (свой ID можно узнать
  у бота **@userinfobot**). Если оставить пустым — паузу сможет ставить
  кто угодно, это ок для теста.

Эти же три параметра можно не трогать в коде, а задать как переменные
окружения (`BOT_TOKEN`, `MC_USERNAME`, `MUSIC_USERNAME`, `MANAGER_IDS`) —
так удобнее при деплое на хостинг (см. Шаг 4).

## Шаг 3. Проверить локально (если есть свой компьютер с Python)

```bash
pip install -r requirements.txt
export BOT_TOKEN="твой_токен_сюда"
python bot.py
```

Дальше:
1. Найди своего бота в Telegram по юзернейму, нажми **Start**
2. Добавь его в тестовую группу (свою, не рабочую — для проверки)
3. В группе напиши `/new` и пройди мастер (тип → стол → VIP → песня)
4. Бот опубликует карточку заявки с кнопками — понажимай «Готовы» →
   «Объявить» → «Выполнено», проверь `/pause` и `/resume`

Если это работает локально — переходи к деплою, чтобы бот жил постоянно,
а не только пока у тебя открыт терминал.

## Шаг 4. Деплой, чтобы бот работал круглосуточно

Проще всего — **Railway** (бесплатного лимита хватает для одного клуба):

1. Зарегистрируйся на railway.app (можно через GitHub)
2. Создай новый проект → **Deploy from GitHub repo** (тебе понадобится
   закинуть эти 3 файла — `bot.py`, `requirements.txt`, `README.md` — в
   свой репозиторий на GitHub; можно через веб-интерфейс GitHub, без
   терминала)
3. В настройках проекта на Railway добавь переменные окружения:
   `BOT_TOKEN`, `MC_USERNAME`, `MUSIC_USERNAME`, `MANAGER_IDS`
4. Railway сам поставит зависимости и запустит `python bot.py`
5. Проверь в логах Railway строку «Бот запущен» — значит всё поднялось

Альтернатива — **Render.com**, процесс аналогичный (Background Worker,
не Web Service, так как это бот с polling, а не сайт).

## Что дальше можно улучшить

- Заменить память процесса на нормальную БД (SQLite хватит), чтобы очередь
  не терялась при перезапуске бота
- Разделить карточки по топикам (темам) группы, если группа — супергруппа
  с включёнными топиками
- Добавить кнопку «Отменить» с подтверждением, чтобы случайно не снести
  чужую заявку
